FCNN on FPGA: a neural network built from Verilog primitives

No neural-network IP core, no HLS. Every multiplier, adder, and neuron in this digit classifier is hand-written Verilog, synthesized for a Zybo Z7, driven by weights trained in TensorFlow.

Most "neural network on FPGA" projects start from a vendor IP core or an HLS toolchain that compiles C++ down to RTL. This one starts from primitives — a multiplier, an adder, a neuron built out of both — and composes upward until the composition is the network: a 256-input, 128-unit hidden layer feeding a 10-unit output layer, classifying digits.

What a neuron actually does here

Each neuron owns its own slice of weights, loaded from a file at startup. On every clock cycle it pulls in one input value and the matching weight, multiplies them, and adds the result into a running accumulator — walking through all 256 inputs one at a time before adding a bias and applying a hardware ReLU: if the accumulated value is positive it passes through, otherwise the neuron outputs zero. One neuron, one shared multiplier and adder, reused 256 times in sequence — small, but slow per-neuron by design.

Where the speed actually comes from

What makes the layer fast isn't a faster neuron — it's that the hidden layer doesn't contain one neuron, it contains 128 of them, each hand-instantiated with its own dedicated weight file, all reading the same input bus and firing in parallel on the same clock. Every neuron is doing its own 256-step serial accumulation at the same time as all 127 others. The output layer works the same way, at a smaller scale: 10 neurons, each looking at all 128 hidden-layer outputs. Serial inside a neuron, parallel across a layer — that trade-off is the whole design.

Getting trained weights into hardware

The network is trained in TensorFlow at full precision, then quantized to 16-bit fixed point and split into one weight file per neuron, loaded into on-chip memory at simulation/synthesis time. The hardware that comes up on the board is running the same weights the Python model was trained to produce, just re-expressed in fixed point and physically distributed one file per neuron instead of one big weight matrix.

Deciding the digit: argmax, and a real hardware exponential

The output layer produces 10 raw scores, one per digit. Picking the winner could be as simple as taking the largest of the 10 — and that's exactly what the decision path does. But the softmax stage does more than that in parallel: it runs each score through a genuine hardware implementation of e^x, built as an iterative Taylor-series expansion — multiply-accumulate a running x/n term into a sum, about eighteen cycles per class — to produce the actual softmax probabilities, not just a ranking. Because softmax is monotonic, the class with the highest raw score is always the class with the highest probability, so the argmax over raw scores and the argmax over true probabilities agree — the Taylor-series unit computes something genuinely more informative than the decision needs, which is a legitimate design call when the probabilities themselves might matter for future work, even if today's decision path doesn't need them.

What's verified, honestly

Verification depth here is intentionally modest for a personal project: the adder primitive has a real testbench, and the neuron's behavior was checked against a captured simulation waveform — not a formal, end-to-end testbench across the full 256-128-10 network. That's the honest state of it, and it's a smaller claim than "it works," but it's the one the repo actually supports.

What's next

There's a further extension of this same idea — streaming image data on-chip and convolving it against a kernel before handing results back to Python — that lives in a separate piece of work, not this repo. Link coming once it's ready to show.
