Spec-Aware Semantic-Temporal Debug Agent

A simulation waveform can carry thousands of signals across millions of cycles. An LLM's context window can't. This agent's entire job is figuring out the handful of signals and the narrow slice of time that actually matter for one question, before spending a single token on the answer.

Waveforms, briefly

When a digital simulation runs, the simulator can record every signal's value over time into a waveform database — effectively a giant table of "signal, time, value." A VCD (Value Change Dump) is the common text interchange format for this: every time a signal changes, one line records the new value and the timestamp. For anything past a trivial testbench, that file is enormous — a few seconds of real simulated time can produce millions of change events across thousands of signals.

Why "just paste the waveform" doesn't work

The obvious approach — dump the relevant waveform region to text and hand it to an LLM — fails for two related reasons. First, cost and context: even a "small" slice can be tens of thousands of lines, most of them irrelevant clock toggles and unrelated signals. Second, and more important, signal: burying the three signals that actually matter inside ten thousand lines of noise makes the model's job harder, not easier — LLMs are not immune to being distracted by irrelevant context, and a debug agent that reasons worse with more data defeats the purpose.

The semantic-temporal query adapter

The fix is to never hand the model raw waveform data — only ever a narrow, purpose-built slice, fetched on demand through a tool. The adapter does two kinds of narrowing:

  • Semantic — given a natural-language question ("why did the FIFO's full flag stay high after the drain sequence"), map it to a small set of candidate signal names using the design's signal hierarchy and naming conventions, plus whatever spec text is available describing that block's intended behavior. This step never touches the waveform itself — it's pure name/spec matching.
  • Temporal — once candidate signals are identified, find the time window actually relevant to the question (the edge where a flag changed, plus a small margin before and after) rather than the whole run. A question about one transition doesn't need the previous ten thousand cycles.

Only after both narrowings does the agent extract the actual signal values, from the waveform database's own export utility, for exactly that signal set and exactly that window — and that's the only piece that reaches the model.

Why MCP fits this well

Model Context Protocol gives the agent a clean way to expose "query a signal window" as a callable tool with a typed schema, rather than stuffing waveform-fetching logic into a prompt template. The agent's reasoning loop is: propose a signal/window hypothesis, call the tool, look at the (small) result, refine the hypothesis if the first guess was wrong, and repeat — usually two or three rounds before it has enough to answer. Each round costs a few hundred tokens instead of the entire waveform, and each round is a real, verifiable data fetch rather than the model hallucinating what a waveform probably looks like.

Where it plugs in

This agent runs as another atom in the same orchestrator framework — triggered by the regression lifecycle manager whenever a failure gets escalated rather than auto-fixed, so a component owner's first look at a real failure already comes with a first-pass hypothesis and the exact signal window that supports it, instead of a raw log and an invitation to start from zero.

Where narrowing can go wrong

The semantic step is the one place a bad guess costs the most: if the naming/spec match misidentifies the relevant signals, the temporal narrowing and the query that follows are precisely targeted at the wrong thing, and the agent will confidently answer a question that wasn't asked. The mitigation is to keep the semantic step's confidence visible — when the match is ambiguous, the agent surfaces its top few candidate signals instead of silently picking one, so a wrong guess is easy to spot and correct rather than buried in a plausible-sounding wrong answer.
